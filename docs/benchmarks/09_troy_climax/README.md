### 效率分析

H3 文本与 Stage1 的六段合计为 **193.18 秒**，由两个精修版本共享。上表前两项是把这个值与离线精修请求相加得到的计算阶段估计，**不是另一次完整服务请求的墙钟测量**。实际原服务通用版本六次端到端请求合计为 **406.56 秒**；它使用已启动的生产编译路径，与这次关闭编译的受控精修会话不同。

通用/专用精修的每段中位数分别为 **40.316 / 40.287 秒**。第一个通用请求为 50.11 秒，其余两种均约 40 秒；去掉第一对后，两组五段合计仅相差约 0.12 秒。因此不能把专用版本总时间少约 10 秒归因为提示词加速。两种缓存都提供固定 1024 长度的后连接器特征。

Ingredients/MSR 纯去噪循环累计分别为 **343.43 / 339.95 秒**；总时间的差额主要在 diffusion block 内的非去噪工作，包括权重构建和 LoRA 融合。它们的 diffusion block 总时间分别为 727.24 / 795.83 秒。这不支持“MSR 去噪本体普遍更慢”的结论；每段参考数量也由前四段的 2 张变为最后两段的 5 张。

本轮还单独记录了 Ref2VA 服务启动 430.66 秒、共享精修模型初始化 50.54 秒、18 个离线提示词准备进程 126.07 秒、原生 H3 诊断解码 165.63 秒，以及最终 FL2VA 服务恢复启动 473.84 秒。上述准备、诊断与恢复时间不混入每版生成时间。

稳定精修请求的 PyTorch 峰值分配约 41.03 GiB；第一次通用请求为 44.06 GiB。Ingredients/MSR 峰值约 39.53 / 39.62 GiB。这里统计的是 PyTorch 分配，**不是全机统一内存，也不是完整 H3 常驻服务的峰值**，不能据此比较全链路最低硬件要求。

### 质量与叙事分析

- 原生 H3 的进城片段已经提前打开舱门、出现梯子；通用精修又改写木材纹理。因此剧情错误与材质错误有不同来源。
- 夜间三段构成 H3 实际接续链，交付共约 13.54 秒。后段重复的红衣士兵、额外盾牌在原生 H3 中就存在，专用精修未能消除。
- MSR 的末段抽帧呈现红衣士兵落地、蓝衣士兵下梯，人物数量比本次 H3 后段更符合目标。但红衣和蓝衣的脸、发型、盔甲细节仍不能认定与原参考精确一致；动作与装备要求也有偏差。
- Ingredients 把参考拼图当作成片内容，是本轮当前输入形式的失败。没有据此断言该模型普遍无法生成故事，也没有通过后期裁掉黑边或拼图来掩盖失败。
- Ingredients/MSR 的片段间为独立生成的剪辑，不能把时长对齐当作原生动作接续能力。H3 的冻结检查只证明条件数据不被改写，不能保证故事状态、角色数量和未来动作正确。
- 本轮没有建立人脸身份分数、动作流畅度量表或音画同步评分；观察来自故事中点、夜间关键时刻及部分完整尺寸帧。完整解码只确认文件技术有效。

## 本轮协议

- 通用和专用 LTX：同一份 H3 Ref2VA 捕获，同一个常驻精修模型，同一组 3 步噪声表和 LoRA 强度；关闭编译，逐镜交替运行顺序。
- H3 的第 2、5、6 段实际使用 22 帧动作上下文与 24 帧音频上下文，检查冻结条件。第 1、3、4 段为独立镜头。
- Ingredients、MSR：原生 LTX 8 步，逐镜独立生成。为了在同屏对照中对齐剧情，第 2、5、6 段裁掉末尾 19 帧；这不构成动作接续实现。
- 四种方法共用每个镜头的视觉资产和动作要求。前四段只提供木马/广场和该镜构图；最后两段才加入两名角色和装备参考。
- 首轮 H3 使用全角色参考，白天提前出现希腊士兵及舱门动作。该尝试保留在 `initial_all_subject_references/`；调整参考策略后统一使用 v2 输入，不能把参考策略调整归因于某一个模型。
- 参考分镜由内置 image_gen 使用上一轮分镜作视觉参考生成，原图及分镜裁切保存在 `assets/`。角色身份参考仍来自上一轮低分辨率裁切，新增分镜不等于经过验证的多角度身份资料。

## 耗时统计

分别记录服务启动、H3 文本与 Stage1、精修模型初始化、精修请求、离线文本准备、参考编码、原生 LTX 去噪循环与解码输出。验证和最终拼接不计入生成阶段，单独保留队列墙钟时间。

Ingredients/MSR 使用官方 block 模型生命周期，每个 block 会加载/释放模型；其 block 时间包含加载。不能把这些时间当成常驻服务吞吐。PyTorch 峰值分配不等于 Spark 全机统一内存占用。

前两种原始输出 1344×768，后两种 768×448；均为 24 FPS。最终比较片统一重采样音频为 32 kHz 双声道，原生 LTX 的 48 kHz 原始输出另外保存。

## 质量检查

人工检查木马是否保持木制刚性结构、轮子与平台是否合理、进城阶段是否提前出现士兵、停驻及昼夜转换是否完成、舱门位置是否保持、士兵是否真正从舱门沿梯子出来，以及两名角色的脸、披风、盔甲与装备归属。

文件解码、帧数和冻结条件验证只确认技术有效，不代表剧情与一致性通过。一次故事、一次 seed 的筛查不能代表模型总体排名。
