# 木马计 · V2 小型工程回归

范围是 S10 下梯、S15 剑矛交锋、S16 双人抬闩、S20 大军团群战。4个镜头 × 3种控制 × 2个种子 =24个新的5秒视频。旧版100秒影片保留为历史对照。

## 输入与控制

- `shot_specs.json` 记录起始/结束状态、角色装备、人数、空间、不可变条件与动作验收标准。
- 静态帧全部通过 Spark 上的自托管 Qwen Image2.1 BF16、40步、CFG1生成，没有 Turbo LoRA。`guides/` 是程序生成的位置与机械示意，供 Qwen 参考；不是交付的电影画面。原始 PNG、提示词、参数、引用哈希和失败候选均保留。
- A：MSR参考图；B：相同MSR参考图＋第0帧 latent 注入；C：相同MSR参考图＋第0帧注入＋原生第120帧 guiding tokens。末帧是引导而非保证像素完全一致。
- 组内使用相同的新提示词、相同MSR槽位、同一种子、同一权重/LoRA强度、8步、121帧@24fps和768×448。交付裁去上下各8像素并保留前120帧，得到768×432、5秒片段。导出末帧为4.958秒，末图引导位置5.0秒。
- 参考条件保留已验证旧版适配器。每个33帧参考序列首帧有负时间偏移，后续VAE时间单元保留间距；不将全部参考tokens误称为固定在单一负时间点。`conditioning_check.json` 检查原生类、首/末帧位置、重排和裁剪的组合。
- 同一镜头提示词缓存复用6次。作业有独立的内容指纹，只有相同输入及相同输出哈希才可续跑。修改关键帧、角色引用、参数或提示词会使相应输入指纹变化。

## 执行与验收

`run_trials.py` 的常驻 transformer 模式必须先通过同一输入、种子和条件的保守生命周期/常驻生命周期 latent 数值回归；通过后24个组内任务采用一致执行路径。没有盲目切换 ModelRegistry 缓存开关：结构缓存本身仍会重新加载权重。

`result.json` 的 TECHNICAL_PASS 只代表文件、帧数、尺寸、音轨及完整解码正确。质量评价另存 `quality_review.json`，每段取0.5秒间隔加末帧，共11个时间采样；它不能替代逐帧动作和音轨终验。硬性状态冲突不得进入正式合格素材清单。较好但仍有缺陷的样片用“诊断候选”单独呈现。

S16 输入检查已经发现硬性机械结构缺陷：Qwen把固定托架画成闭环，抬高后还会移动闭环并新添支持件。该镜头仅作为约束诊断，不能因为生成成功而计入合格视频。参见 `keyframe_review.json`。其余静态帧也保留具体限制。

## 文件与运行

- `prepare.py` 冻结ShotSpec及Qwen请求；`generate_frame.py` 只访问模型机loopback。
- `session.py` 管理图像/视频互斥会话；关闭图像父进程后还须等待CUDA worker真正退出，才进入视频阶段。旧执行因瞬时检查失败触发恢复，经过已验证归属的进程清理后由 `video_session.py` 续跑；所有原始收据保留。
- `freeze_trials.py` 生成24个有内容指纹的输入；`run_trials.py` 编码4个提示词、进行数值探针并生成真实视频片段。
- `inspect_trials.py --final` 在本机验证拷贝、完整解码和时间采样；`build_review.py` 展示所有候选与人工结论。
