# Qwen-Image-2.1 加速实测

日期：2026-09-29。机器：DGX Spark / NVIDIA GB10 / 128 GB 统一内存。

结论：三项均已实测。批量资产优先使用六步 Turbo 并复用模型，热态约 11–14 秒；保留原版 40 步时，SGLang 原生服务约 35–42 秒。Turbo 当前入口的首次加载仍约 202 秒，不能把热态速度当成冷启动速度。

## 测试范围和计时

按顺序测试六步 Turbo、单进程连续出图、SGLang 原生后端。场景为 1344×768；透明道具与参考图改色为 1024×1024。三类请求使用初次验收的相同提示词和种子；所有改色请求使用同一张原版红茶壶，避免参考图差异影响比较。

每个运行配置先生成一张场景图预热，再交替执行三种请求各三次。报告中位数，同时保留最小值、最大值和每张 PNG 的 SHA-256。重复相同种子用于比较速度和可重复性，不代表覆盖多个随机结果的质量评估。

Diffusers 的生成计时包含编码、去噪和解码，并同步 CUDA；PNG 写入单独记录。SGLang 使用 HTTP 整体延迟，包含服务端 PNG 编码和响应传输。两者均不包含冷启动；不是完全相同的计时边界。

## 第一项：六步蒸馏

使用 Viggle Turbo v0.2.1 r256 BF16 动态 LoRA，不合并进基础权重。适配器大小 1,359,147,904 字节，SHA-256 为 `2a0148f5c73abbed5f97da5ea356e439318aadb281d01fce4af39cdf43728803`，下载后完整校验通过。

| 用例 | Turbo 六步中位数 | 最快–最慢 | 原版四十步中位数 | 加速倍数 |
| --- | ---: | ---: | ---: | ---: |
| 场景 | 11.15 秒 | 11.10–11.24 秒 | 52.83 秒 | 4.74× |
| 透明红茶壶 | 11.22 秒 | 11.21–11.22 秒 | 52.57 秒 | 4.69× |
| 参考图改蓝 | 14.31 秒 | 14.22–14.31 秒 | 59.73 秒 | 4.18× |

九张正式 Turbo 请求生成合计 109.97 秒，包含 PNG 写入为 112.85 秒。最大 CUDA 分配约 40.14 GiB，包含完整模型、动态适配器和请求工作区。

六步使用 `sigmas=[1.0, 0.9375, 0.875, 0.75, 0.5, 0.25]`、`shift_terminal=None`、CFG 1；不是直接对原版减少迭代次数。[发布者配置](https://huggingface.co/Viggle/Qwen-Image-2.1-viggle-turbo)

## 第二项：一次加载、连续请求

本轮实际加载拆分：

- CPU 加载：1.00 秒。
- 挂载 LoRA：0.11 秒。
- `.to("cuda")` 并同步：200.87 秒。
- 合计：201.97 秒。这里尚未进一步拆分 CUDA 初始化、内存分配、权重传输各自占比。

首次 Turbo 场景生成 12.01 秒，因此从加载开始到首张生成结束仍约 214 秒，不含 Python 导入和 PNG 写入。后续请求复用同一个模型对象，不再支付约 202 秒启动成本。

同进程关闭 LoRA 并恢复基础 scheduler 后，原版九张正式请求合计 495.64 秒，单张仍为 52.6–59.7 秒。复用进程解决反复加载，蒸馏解决每张推理耗时，两项可以叠加。

原版对照期间 LoRA 权重仍驻留但禁用，因此本轮原版峰值内存包含适配器；不宜把该峰值当成纯原版部署所需内存。

## 第三项：SGLang

| 用例 | SGLang HTTP 中位数 | 最快–最慢 | 相对 Diffusers 原版的加速 |
| --- | ---: | ---: | ---: |
| 场景 | 35.57 秒 | 35.32–35.87 秒 | 1.49× |
| 透明红茶壶 | 35.23 秒 | 34.99–35.37 秒 | 1.49× |
| 参考图改蓝 | 41.68 秒 | 41.67–42.51 秒 | 1.43× |

各三次正式请求全部通过尺寸、像素非均匀和透明通道检查。该运行从启动命令到健康就绪为 70.03 秒，包含加载和服务内部的短预热；第一张完整 40 步场景请求为 36.45 秒，两项合计约 106.48 秒。此冷启动只测了一次，计时起点与 Diffusers 的纯模型加载计时不同。

首次尝试因启动 PATH 未包含虚拟环境中的 `ninja` 导致请求失败；修正后重新完整运行。失败尝试未计入上表。再次启动前的端口探测增加 `SO_REUSEADDR`，避免关闭连接后的端口状态误报。

隔离目录 `/home/admin/qwen-image-2.1-runtime/sglang-venv`；执行源码固定为 SGLang `5828cd49276a419402b316aec0236e5c2161e46d`，以 `PYTHONPATH` 指向源码运行。PyTorch 2.13.0+cu130、Transformers 5.12.1、Diffusers 0.37.0。

使用 `--backend sglang --performance-mode speed --attention-backend torch_sdpa`，单 GPU、单图、40 步，保留默认条件缓存。没有开启量化、Cache-DiT 或额外损失性加速。缓存可利用重复提示词和参考图，属于服务默认行为，不能把全部收益归因于单个算子。

安装环境中的 Python 头文件使用既有 Sol-Spark 私有 sysroot；cuda-tile 从 NVIDIA 官方索引取得并验证 SHA-256，解决主机访问其索引超时问题。没有升级系统 CUDA 驱动或修改 Sol-H3 环境。

## 画面验收

原版和 Turbo 三类输出均可解码，尺寸正确。透明道具与改色的 Alpha 范围为 0–255，近透明区域约 70%；在浏览器棋盘格背景上确认实际透明效果。

关闭 Turbo 后的全部原版对照 PNG 与首次验收对应图片 SHA-256 一致。SGLang 三类输出也通过检查，画面与原版基本一致，但像素并非完全相同；对应场景、红壶、蓝壶的 RGBA 8 位平均绝对差分别为 1.099、0.419、0.295，此数值仅描述差异，不是通用画质评分。

Turbo 场景保留了左侧窗户、陶器架、工作台等提示内容；凳子、台面摆设和表面纹理与原版存在变化。茶壶改色成功，主体轮廓和视角基本保留。观察只覆盖这组三种素材，人物身份、多参考合成、密集文字和完整图生视频流程尚未验收。
