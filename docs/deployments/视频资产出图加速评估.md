# 视频资产出图加速评估

评估日期：2026-09-29。目标机器：DGX Spark / GB10 / 128 GB 统一内存。
本文为初次方案评估；用户随后批准三项测试，其本机结果单独记录在 [加速实测](Qwen-Image-2.1加速实测.md)。下文预估和上游数字不等于本机实测。

## 结论

优先改为资产阶段一次加载、连续处理请求，再测试 Qwen-Image-2.1 的 Viggle Turbo v0.2.1 六步适配器。建议将约 1 MP 热态单图 10–15 秒作为初步验收目标，而不是性能承诺。复杂角色编辑保留原始 40 步兜底；普通场景图可另测 Z-Image-Turbo。

## 已确认的本机瓶颈

当前 `generate_qwen_image_21.py` 每次进程启动都加载完整流水线，出图后退出。

| 既有用例 | 加载 | 实际生成 | 两项合计 |
| --- | ---: | ---: | ---: |
| 1344×768 场景 | 202.85 秒 | 53.68 秒 | 256.53 秒 |
| 1024×1024 透明道具 | 186.12 秒 | 52.86 秒 | 238.98 秒 |
| 1024×1024 参考图改色 | 212.61 秒 | 59.16 秒 | 271.77 秒 |

证据：`outputs/qwen-image-2.1-acceptance/*.json`。合计不包含 Python 导入和 PNG 写入。
直接 CUDA 加载已在改色用例尝试，未消除慢启动。保持模型加载可摊薄启动成本，但首张冷启动仍存在，需要单独优化和报告。

## 优先方案

1. **复用模型实例。** 同一个 worker 顺序处理一批场景、角色和道具。这里的“一批”是多次单图请求复用模型，不是增加 GPU tensor batch size。固定常用输出规格，记录冷启动和热态耗时。
2. **复用底模加载六步蒸馏 LoRA。** 上游当前推荐 v0.2.1，r256 约 1.3 GB；也提供约 680 MB 的 r128。使用指定 sigma 节点及 scheduler，而不是直接把基础模型从 40 步减成 6 步。作者报告约 5 倍端到端加速，不能当成本机测量。复杂编辑、身份保持和密集小字仍可能退化，RGBA 示例可运行但未做充分定量评估。[Viggle 模型卡](https://huggingface.co/Viggle/Qwen-Image-2.1-viggle-turbo)
3. **在同一工作负载对比运行时。** SGLang 已给出 GB10 配置；其 1024²、40 步热态 HTTP 中位数为生成 35.36 秒、编辑 42.23 秒，包含 PNG 序列化，不包含启动。与本机 53–59 秒仅构成优化线索，提示词和软件不同，不能视为严格 A/B。[SGLang 官方方案](https://docs.sglang.io/cookbook/diffusion/Qwen-Image/Qwen-Image-2.1)

六步版本需遵循的关键配置：

```python
num_inference_steps = 6
sigmas = [1.0, 0.9375, 0.875, 0.75, 0.5, 0.25]
true_cfg_scale = 1.0
# FlowMatchEulerDiscreteScheduler 的 shift_terminal 应为 None。
# 使用动态 LoRA；上游指出合并进 BF16 权重会损失适配器更新。
```

先在现有隔离环境验证 LoRA，再决定是否换 SGLang。不能将 SGLang 官方基础模型测试当成对 Viggle LoRA 的联合验证。

## 视频工作流配合

建议顺序：整理分镜与提示词 → 加载出图模型一次 → 连续生成/修改资产 → 人工或业务规则选定资产 → 释放出图模型 → 加载并连续执行视频任务。

现有语言模型约占 77 GiB CUDA 分配，图像任务约 37–39 GiB，不能仅凭标称 128 GB 就承诺语言、图像、视频三套模型同时常驻。现有互斥锁应保留，模型切换需计入整体耗时。

Sol-H3-Spark 的既有约 67 秒结果是预热后文生视频测试；没有本项目图片资产接入图生视频的完整验收，不能直接把两个耗时相加当作已验证的图生视频速度。

优先保持当前 1344×768 场景与 1024² 道具规格。可另测 1024×576 的构图预览，再只对选中资产生成最终尺寸；低分辨率的细节和身份保持必须比较，放大不能恢复缺失内容。

## 备选和后续优化

- **普通场景：Z-Image-Turbo。** 官方定位为八次网络评估的文生图模型，不能视为 Qwen 的参考编辑与透明输出等价替换。[官方模型卡](https://huggingface.co/Tongyi-MAI/Z-Image-Turbo)
- **同类硬件的速度参考：** NVIDIA 论坛一位 GB10 用户报告 Z-Image-Turbo 1024² 编译预热后约 7.2 秒；这是个人测量，尚未在本机复现。[原始测试记录](https://forums.developer.nvidia.com/t/image-diffusion-speeds/369095)
- **编译：** Diffusers 提供 Flex Attention 配合 transformer 编译；必须一起启用并预热。无编译的 Flex 路径可能更慢且占用大量内存。先固定尺寸测净收益，不在每个请求重新编译。[Diffusers 文档](https://raw.githubusercontent.com/huggingface/diffusers/main/docs/source/en/api/pipelines/qwenimage21.md)
- **量化：** 留到第二轮。减少权重体积并不保证更低延迟；GB10 的内核兼容性和 RGBA 质量需要验证，不能搬用 B200 的 NVFP4 成绩。

## 验收标准

以现有场景、透明茶壶、改色用例为最小回归集，增加人物身份保持和多参考合成。先对比原版 40 步与 Turbo 6 步；各自预热后重复测试，记录中位数、最慢请求、峰值内存及冷启动。

检查实际画面、角色一致性、透明边缘和编辑指令遵循，再把选中资产接入真实视频任务。最终交付指标应同时包含热态出图和模型切换后的完整流程耗时。
